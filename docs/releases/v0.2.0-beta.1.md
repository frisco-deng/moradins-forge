# Moradin Forge v0.2.0 Beta 1

## Summary

This beta promotes Moradin Forge from public alpha to the first beta release of
the local agent adoption harness.

## Highlights

- Adds Linux, macOS, and Windows bootstrap entrypoints.
- Keeps host tooling installation request-only.
- Hardens public export, sidecar, and start-card leak scanning.
- Moves the optional workbench to React 19, the patched React Router 8 line,
  Vitest 4.1.10, and Node.js 24 for hosted UI and security gates.
- Adds a seven-day Dependabot cooldown for Python, npm, and GitHub Actions
  updates.
- Adds README visual overview charts for adoption flow, safety boundaries,
  written surfaces, and token-saving bootstrap.
- Stages sidecars before atomic cutover and records every managed-file hash.
- Adds an approval-gated rollback that refuses modified or unowned content and
  restores an owned `AGENTS.md` patch exactly.
- Produces a checksummed public archive, SPDX SBOM, release manifest, and
  current-SHA transactional dogfood evidence.
- Separates stable, reproducible release outputs under `artifacts/release/`
  from disposable proof under `artifacts/dogfood/`.

## Runtime Notes

- The Forge command-line and payload surfaces require Python 3.12 or newer.
- The optional workbench requires Node.js 24 or newer.

## Non-Goals

- Forge does not auto-install host tools.
- Forge does not run adoption without explicit approval.
- Forge does not claim 1.0 stability until cross-platform external-machine
  evidence and release artifact contracts exist.
- Forge does not enable signing, platform, or cross-platform release-candidate
  lanes as part of the core artifact contract.
- Existing sidecars are not upgraded in place; overwrite remains blocked until
  a separate transactional upgrade contract is approved.
