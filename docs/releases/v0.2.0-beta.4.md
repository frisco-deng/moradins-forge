# Moradin Forge v0.2.0 Beta 4 Development

## Starting Point

Beta.4 starts from the verified public `v0.2.0-beta.3` tag at
`301689fd866cfd8307787cdecbb995c821502e2a`. This development branch advances
the package, payload, workbench, User-Agent, and release-artifact version
surfaces together to the `v0.2.0-beta.4` development target.

The normal release predecessor and rollback target are both
`v0.2.0-beta.3`. Transactional sidecar rollback and the sidecar ownership
lineage anchor remain separate adoption contracts.

## Development Stack

- The security-unblock change resolves transitive `nanoid` to 3.3.18, asserts
  the lock regression, adds the PR-capable `dependency-readiness` check,
  updates dependency submission to the reviewed v0.1.4 action contract, and
  adds a scheduled full security audit. It remains a separately reviewed PR;
  replacing the impossible required `submit-dependencies` PR check is an
  explicit admin action after that PR is green.
- Tooling Suite V2 adds aggregate network-free doctor output, digest-bound
  protected-state and transition records, component checkpoints, retry/resume,
  failure-local rollback, idempotent reapply, and V1 receipt compatibility.
- Connected installation now has native Linux/WSL, macOS, and Windows
  entrypoints. Complete air-gap kits remain Linux-only.
- Linux managers are bound to verified absolute paths. Air-gap target images,
  repository metadata, install packages, and rollback packages share one
  frozen snapshot, including the Arch snapshot.
- Extended adds portable archive/foundation, Python QA, IaC, automation,
  recovery/transfer, and security capabilities. Terraform and Packer remain
  selectable manual BUSL handoffs rather than default redistribution content.
- Apache-2.0 licensing, compatibility/support policy, vulnerability reporting,
  and an evidence-based v1.0 readiness checklist are public.

Dependency maintenance remains split by risk: Ruff policy expansion and the
browser stack are reviewed separately from ordinary updates. CodeQL default
setup remains a human-enabled, non-required beta.4 signal until it proves
stable. These development changes are not evidence of a beta.4 release.

## Release Boundary

Beta.4 is development-only until its own review, reproducibility, security,
platform, air-gap, and human promotion gates pass. No beta.4 tag or release is
authorized by this handoff. Signing, production readiness,
release-candidate-manifest, platform signing, and production promotion remain
deferred, and Forge does not create a `prod` branch or environment.

The first v1.0 release candidate additionally requires stable V2 contracts,
keyless signed archive/SBOM/provenance/manifest artifacts, independent clean
machine qualification, Linux offline rollback proof, required stable CodeQL,
zero unresolved high/critical vulnerabilities, and a 14-day observation
period without a release-blocking regression.
