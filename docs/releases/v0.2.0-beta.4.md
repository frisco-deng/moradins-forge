# Moradin Forge v0.2.0 Beta 4 Development

## Starting Point

Beta.4 starts from the verified public `v0.2.0-beta.3` tag at
`301689fd866cfd8307787cdecbb995c821502e2a`. This development branch advances
the package, payload, workbench, User-Agent, and release-artifact version
surfaces together to the `v0.2.0-beta.4` development target.

The normal release predecessor and rollback target are both
`v0.2.0-beta.3`. Transactional sidecar rollback and the sidecar ownership
lineage anchor remain separate adoption contracts.

## Initial Work Queue

- **Dependency-submission protection:** keep actual dependency submission
  enabled on protected `main`, but replace the impossible PR requirement for
  the push-only `submit-dependencies` job with PR-capable validation before the
  next protected-branch rules change. Any branch-protection mutation remains
  an explicit admin approval point.
- **Dependency-submission action:** refresh and validate PR #19 separately.
  The beta.3 `main` run completed its submission but warned that the pinned
  action did not recognize the configured `detectors` input.
- **Grouped updates:** refresh PR #36 as the first npm minor/patch candidate;
  refresh PR #33 separately and diagnose its failing verify check. Preserve
  the seven-day cooldown and do not mix Python and UI lockfile updates.
- **Stale dependency PRs:** PRs #22 through #30, #34, and #35 are conflicting
  or overlap newer grouped/current dependency state. Confirm coverage, then
  close or recreate them instead of resolving stale lockfiles in place.
- **CodeQL coverage:** GitHub reports CodeQL default setup as `not-configured`
  for Actions, JavaScript/TypeScript, and Python. Pilot CodeQL independently
  and make it required only after its signal and runtime are stable.

Dependabot and secret-scanning currently report zero open alerts. This queue
tracks maintenance and coverage work; it is not evidence of a beta.4 release.

## Release Boundary

Beta.4 is development-only until its own review, reproducibility, security,
platform, air-gap, and human promotion gates pass. No beta.4 tag or release is
authorized by this handoff. Signing, production readiness,
release-candidate-manifest, platform signing, and production promotion remain
deferred, and Forge does not create a `prod` branch or environment.
