# Escalation Rules

- Pause only the affected write when target adoption or a root workflow change
  is outside the accepted scope. Prepare the exact proposed change for review.
- Resolve conflicting guidance through task authority and the current canonical
  contract. Preserve superseded records as history; investigate unresolved facts.
- Missing tools trigger readiness evidence and supported alternatives. Host
  installation remains request-only; continue independent authorized work.
- Failed sidecar verification triggers bounded diagnosis and owning-component
  repair, or verified rollback where authorized. A failed check is not completion.
- Investigate an unclear write set from repository evidence. Pause only the
  affected apply lane when a material target or write-scope decision cannot be
  inferred; continue unrelated validation and rollback preparation.
